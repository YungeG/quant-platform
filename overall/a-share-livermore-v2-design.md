# A股 Livermore V2 预注册设计

- **状态：** frozen before execution
- **研究问题：** 将低换手因子彻底移除后，“大势确认→领导行业→领导股突破→ATR风险单位→只给赢家加仓”能否形成稳定的A股趋势策略
- **数据窗口：** 2016-01-01—数据库最新完整日
- **资金：** 40万元

## 1. 市场状态

使用数据库中的申万A指 `801003.SI`：

- 趋势条件：指数累计复权值高于120日均线；
- 宽度条件：历史可交易股票中，复权收盘高于各自60日均线的比例 > 50%；
- `ON`：两个条件均满足，允许开仓和加仓；
- `WATCH`：只满足一个条件，只持有，不开仓、不加仓；
- `OFF`：均不满足，不开仓、不加仓；已有仓位继续按止损退出，不强制清仓。

## 2. 领导行业

使用申万一级行业日指数和历史行业成员：

- 行业累计复权值高于其60日均线；
- 行业60日收益高于申万A指60日收益。

行业只作布尔过滤，不按Top-N轮动，不搜索行业数量。

## 3. 领导股入场

PIT股票池：

- 流通市值前50%；
- 过去20日平均成交额前50%；
- 上市至少252个交易日；
- 当日收盘至少5元，未停牌；
- 不使用当前名称做历史ST过滤，避免未来函数；历史ST权威缺失作为限制。

每5个交易日检查一次。股票必须同时满足：

1. 当日复权收盘高于此前60日最高收盘；
2. 股票60日收益高于申万A指60日收益；
3. 所属行业通过领导行业过滤；
4. 当日涨幅 < 7%；
5. 市场状态为`ON`。

按60日相对市场收益排序，最多保留20个候选。T日收盘决策，T+1开盘执行。

## 4. A股执行保护

- 一字涨停买入直接取消，不追价重试；
- 次日复权开盘若高于信号收盘 `0.5R` 以上，取消订单；
- 卖出遇停牌或一字跌停，持续顺延；
- 买入佣金+滑点13bp；卖出18bp（含5bp印花税）；
- 100股整手，先卖后买。

## 5. 风险单位和Livermore管理

入场风险：

```text
R = clamp(2 × ATR20 / close, 6%, 12%)
每单位目标名义 = 0.5% NAV / R
```

- 最多4只；
- 首次进入1单位；
- 盈利达到`+1R`加第2单位；达到`+2R`加第3单位；
- 每日最多增加1单位；
- 只有市场`ON`时允许加仓；
- 永不向亏损仓加仓。

退出：

- 初始/硬止损：加权成本下方`1R`，止损线加仓后不得下移；
- 达到`+1R`后，移动止损为“最高收盘价减去`1.5R`价格距离”；
- T日收盘触发，T+1首个可成交开盘卖出；
- 无固定持有期限，不因排名下降退出。

## 6. 冻结分层实验

1. **Entry fixed-20：** 同样市场、行业和突破入场；每只直接25%，固定持有20个交易日，无止损、无加仓。验证入场自身是否有edge。
2. **Risk-managed no-pyramid：** 首次只买一个ATR风险单位；使用硬止损和移动止损，不加仓。
3. **Full Livermore V2：** 风险管理版本上增加`+1R/+2R`盈利加仓。
4. **Benchmark：** PIT大中盘高流动性股票池前一日资格对应的次日等权收益。

固定折：2016—2019、2020—2022、2023—2026。

## 7. Gate

### Stage 1：入场Gate

Entry fixed-20必须：

- 三个固定折至少两个净超额CAGR > 0；
- 全样本净超额CAGR > 0。

若入场Gate失败，总策略直接`NO-GO`，不得再用止损或加仓掩盖坏入场。

### Stage 2：风险管理Gate

No-pyramid相对fixed-20必须改善Sharpe或最大回撤至少20%。

### Stage 3：Pyramiding Gate

Full相对no-pyramid必须提高CAGR或Sharpe，且最大回撤不得恶化超过5个百分点。

### Full GO

还须全部满足：

- 净CAGR高于benchmark；
- Sharpe >= 0.60；
- 最大回撤 <= 35%；
- 三个固定折至少两个净超额CAGR > 0；
- 剔除最佳年份后CAGR >= 0；
- 成本后保留至少70%的成本前CAGR；
- 买入阻塞/跳空取消率 <= 10%，估值缺失率 <= 2%。

只有Stage 1通过但Full未完全通过时才允许`MARGINAL`。Stage 1失败即`NO-GO`。

## 8. 防止后验优化

本轮不搜索MA、ATR、R倍数、突破窗口、宽度阈值、候选数、风险预算或持仓数。任何变体必须作为新候选重新预注册。
