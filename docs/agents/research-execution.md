# 研究任务执行指引

适用于策略研究，以及相关的数据可行性、能力接入、阻塞/耗时复盘。**这是派发与交付规则，不是新增审批、状态机或研究许可。** 已有明确停令、授权边界及预算继续有效；不恢复旧任务、旧余额或监督器。

## 派发前，在现有任务或Issue中回答五件事

1. **交付什么结论？** 区分可行性判断、数据资格、软件能力、科学研究；给出可观察产物和拒绝条件，不以“继续推进”代替目标。
2. **现在能执行吗？** 核对所需数据的单位/状态/时点/完整性与确切公开准备接口、等级、指标。区分已知事实、未核验和缺失；路径或代码存在、合成测试通过不等于数据合格。
3. **允许做什么？** 明确读写范围、样本/holdout边界及累计资源帽，覆盖小样、执行、必要修复和关闭；旧批准不自动覆盖新范围。
4. **怎样验收？** 按下表选择证据，沿用现有工具，不为满足统一模板运行无关检查。
5. **何时停止？** 关键未知项先做有限补证；到约定边界仍不足就明确结束当前评估或暂停其依赖项，不不断扩工程、不把缺证据交给用户“批准为合格”。

派发结论须说明：可直接执行、先补数据依据、先补公开能力，或停止当前路线。这些是事实判断，不是新的任务状态或额外人工批准门；补能力/补数据也不是自动扩建或采集许可。先指出缺口与最小交付，只执行已批准的部分。前置条件未成立，不派发大规模真实执行工程。

## 分开任务，不分裂成更多审批

- **能力建设：** 先用同一公开路径的小型代表性fixture证明成功、失败与重放，再扩展必要用例；没有新证据目标就停止扩建。不能把工程完成叫作策略有效。
- **数据资格：** 交付所需语义/覆盖的依据或明确缺口。有限查证未建立，不等于供应商永远没有能力；未建立也不能进入正式拟合。
- **科学研究：** 输入和能力就绪后，预声明有限试验与选择规则。无合格候选是正常结论，不为进入OOS追加参数、删失败项或移动日期。
- **历史复盘：** 优先读既有报告、日志和代码；不自动打开行情/数据库/凭据、恢复工作树、发布数据或重启旧研究。

## 验收与关闭

| 交付类型 | 必要证据 | 不能替代它的东西 |
|---|---|---|
| 只读调查/指引 | 来源、实际调用或约束、结论与未知项；文档链接及事实核对 | 无关pytest、模型运行或写者命令配额 |
| 软件改动 | 同代码/配置小样、改动半径回归、真实退出与产物；公共seam/兼容/高风险变更按已有合同补齐完整门 | 仅子任务exit0、静态review或旧版本绿灯 |
| 实际研究 | 有限试验及全部失败的闭包、合法分析/选择、适用的验证结论或明确无报告原因 | 合成闭环、源码包校验、收益手算或手选赢家 |
| 输入不足/用户停止 | 已做/未做、缺失依据或实际停止决定、失败及消耗、下一依赖 | 科学阴性、原研究完成或伪造的任务done |

新任务可把可行性评估本身定义为交付；这不回填D009等旧研究的完成状态。任务工具若拒绝与交付类型匹配的证据，披露工具限制并仅暂停受影响步骤，不补无关命令、不改口称已验收。

同一已批准范围内、已有修复余量的普通离线错误可直接修正并重核，不逐文件重新请示；明确次数帽/停令不得绕过。扩大数据、超预算、触碰holdout、凭据/付费/生产或原批准未覆盖的写入/发布时再确认。打包和关闭属于交付，不留到预算耗尽后。

验证按实际改动半径选择：文档核语义/链接及已有相关检查；代码先最小反例，再必要回归；完整门只在合同或风险需要时执行。规划器标记规范文档或未知范围为BLOCKED时，不能降级成普通说明来制造PASS；保留人工核对与自动覆盖的区别。不为本指引新建验证器、benchmark或任务板。

中断先检查现有进程、保存部分改动与已执行证据，再恢复原任务的剩余步骤；不重开同等全量任务或把失败额度退款。报告实际结果、阻塞、下一执行者及是否需用户决定；耗时利用已有记录，区分计算、返工和等待，不拿pytest快几秒代表整条研发提效，缺失历史数据保持未知。
